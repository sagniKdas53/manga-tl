## What was measured today

**Layers pile up.** On the chrome-box B stack (64 pages), 32 pages have the usual three layers
(Inpainting, OCR, Translation). 27 pages have 14 to 21, because every *Redo OCR* or
re-translation adds a new OCR and Translation layer ("OCR (manual-re-ocr)", "Translation
(retry)", …). Only one Translation layer is visible on each page. The panel has no way to fold
or merge them, only delete them one by one.

**Undo is lost on reload.** The editor's undo stack is in memory (`Reader.tsx`, `UndoEntry`):
one entry per element edit, with no layer actions. `layer_edit_history` records each element
save on the server, but nothing reads it back for undo (10 rows on the B stack).

**Tilted text is common, and OCR already measures it.** No element on the B stack is rotated (0
of 5,763): every call site writes `rotation: 0`. From the OCR pieces' quads (the four-corner box
OCR draws round each line), over 763 regions:
- 46 regions are only square pieces (a single glyph has no direction), and 36 have pieces that
  disagree by more than 6°. These must stay level.
- Of the 681 left: 82% within 3° of level, 4.7% at 3–5°, **13% at 5° or more, on 34 of 64
  pages**. Torii rotates 12% of its boxes by 5° or more, on 45% of pages. The two agree.
- The most tilted ones are mostly junk (HNM, 1, nd: short pieces whose angle means nothing). The
  real ones are signs and slanted speech: したから写真送るわ… at 25°, 催眠羞恥調教 at −20°. So
  the rule needs a minimum line length and agreement between pieces, not a plain average.

**The fitter ignores rotation.** `fitTextInBox` (`packages/page-scene/src/layout.ts`) slices the
balloon outline, which is stored in page coordinates, as if the element were level. On a
rotated element the editor would wrap the text into the wrong shape. #179's two reshape bugs (handles
drawn at twice the angle; a vertex drag inflates the box) are confirmed in the code.

**Text boxes are one Japanese column wide** (#244). Free ch. 1 p27: *Then hand over that phone
right this instant!* is set at 11 px in a 43 px box. The region's safe-text area is 57 px and the
balloon lobe 63 px. On B p10 even the detected balloon is only the column (153 px) inside a
balloon about 400 px across.

## F: layers and the editor round

### F1: hiding a region hides its patch (#237)

The region's eye button flips its text element and its patch element together, as one undoable
step, and saves both with explicit `true`/`false`. Today the two sides read a missing `visible`
differently: the scene builder paints a patch only when `visible = TRUE`, but draws text when it
is NULL. Hiding a whole text layer still keeps every patch (R7-D4: that is the cleaned page for
hand lettering).

**Gate:** B p5's 「はは艺」 and p22's two misread SFX, hidden, leave the art as the source showed
it, in the editor and the export.

### F2: OCR fragment overlay (#243)

The backend already sends each region's pieces (`ownershipProvenance`: quads and the reason each
piece was grouped). Add it to `golden-openapi.json` and the frontend types, then add an *OCR
fragments* switch under *Show debug* that draws each piece's quad, with its text and grouping
reason on hover.

**Gate:** sample99's ぬるぬるで shows as text with no piece over it (that is I, #245); p27's two
columns show as two pieces in one balloon.

### F3: Add layer, merge, groups (#178)

- **Panel.** `+ TL` and `+ SFX` become **Add layer** (pick Text, SFX or Patches) and **Merge
  layers** (merge down, merge visible).
- **Only like layers merge:** text with text (Translation and SFX), patches with patches.
  Merging moves the elements into the lower layer and deletes the upper one. A merged patch layer
  keeps every patch as its own element in paint order, so each stays editable (2026-10-01).
- **Groups:** a group is a row in `layers` with type `group`, and other layers point to it with a new
  `parent_id`. Hiding a group hides what is inside, reordering moves the group as one block, and
  merging a group merges its like layers. A group inside a group is not allowed (keeps the panel
  and the scene rules simple).
- **Names:** a `name` column, editable, so "Translation (retry)" is a name, not something
  worked out each time.
- **Schema:** `layers.name`, `layers.parent_id` in `database/init.sql` plus the upgrade SQL
  (LOCK-3); hand edits of `golden-openapi.json`; frontend types.
- **Render:** the scene builder's two queries (text layers and patch layers) also need the
  parent group to be visible. The page-project ZIP carries `name` and `parent_id`, so its format
  version goes from 2 to 3. By the standing no-compatibility rule (R7-D3), version 2 is then
  refused like version 1. Reading it would cost little (it simply has no groups); say if you want
  that exception.

**Gate:** on a 17-layer page, the re-run layers fold into one group, merge into one Translation
layer, and the page renders the same before and after (draw-list compare, no paid QA:
re-renders queue QA unless the page is hand-edited). Save, reload, export: all match.

### F4: undo that survives a reload (#178)

A `layer_ops` table: one row per layer action (merge, group, ungroup, reorder, delete), holding
what the affected rows looked like before and after. Undo writes the "before" rows back, and redo
writes the "after" rows back, both in one transaction. The editor's in-memory element undo stays as
it is. Layer actions use the server's record, so they survive a reload.

Bounded: the last 20 actions per page (the "UI lists need a bound" rule). A newer edit to a layer
an older action touched makes that action no longer undoable; the button says why.

**Gate:** merge, reload, undo: the two layers are back with every element unchanged. Redo
merges them again.

### F5: text box sized to the balloon (#244)

This is output work with an editor face. It changes the geometry each text box starts with, as
E2 does, so it is built right after E2:
1. When a region is the only text in its balloon, start the text box from the safe-text area,
   not the OCR box. This is cheap and fixes p27's small cases.
2. Measure the balloon's free inside on the cleaned page: fill the paper outward from the text,
   up to the outline. That gives the real width where the detected balloon is only the text
   column (p10). Two regions in one balloon split it.
3. LOCK-1 holds: text with no balloon is never widened.

**Gate:** #183's readability check on p27 and p10 beside today's output; no new overlaps (#182).

## E: tilted text at its angle

### E1: reshape on rotated elements (#179), first

Draw the reshape handles outside the rotated group (or counter-rotate them). After a vertex
drag, un-rotate the polygon about the element's centre before measuring the box. E makes 13% of
regions rotated, so this has to work before E ships.

**Gate:** Reader tests on a 30° element: the handles sit on the outline, and the box is the right
size after a drag and after Undo.

### E0: fit the angle rule on Torii first (no code)

Fit the rule on the 270 Torii bundles (`corpus/samples/*/sample*/torii/metadata.json`, 339 of 2,880
boxes at 5° or more), then check it on today's B-stack regions:
- the region's angle is the length-weighted angle of its line pieces; square pieces don't vote
  (B4's rule);
- level below a dead band (start at 4°); near 90° is vertical text, not rotation;
- a piece shorter than about two characters doesn't vote; if the pieces disagree by more than
  about 6°, keep the region level.

**Settled 2026-10-09** (owner's Rotate set, #265, #266; the rule is `scripts/e0/angle_rule.py`):
dead band 5°, a piece votes from 1.5 line-thicknesses, agreement 6°. Two changes to the rule above:
- **Near 45° (#265).** A piece's angle off the nearest axis lies in ±45°, so text at about 45°
  read +44° on one piece and −44° on the next, or the wrong sign on a single piece. Once any voting
  piece is more than 35° off, every piece is read as a line of text along its long edge (±90°).
  This assumes horizontal lines: a vertical column tilted more than 35° would come out about 90°
  off.
- **One stray piece (#266).** If three or more pieces disagree, the one farthest from the
  length-weighted median is dropped, once, before the agreement check.

Report: angle error against Torii, how many regions turn, and every one above 20° looked at.

### E2: the worker writes the angle and an oriented box (#180)

- `merge_regions.py` / `handlers/ocr.py`: compute the angle with E0's settled rule
  (`scripts/e0/angle_rule.py`, ported with its tests). The box is the pieces un-rotated about
  their centre: the level box of a tilted line is too tall.
- `region_merge::union_box` (a hand merge) and *Redo OCR* keep the angle instead of resetting it.
- Settings, by the no-op rule: `OCR_TEXT_ANGLE` (on or off) and its dead band, global with a
  series override. Whether the default is on is decision D4.
- Cleanup is unchanged (it works from the glyph mask).

### E3: fit rotated text to its outline

`fitTextInBox`'s callers (the editor's `elementFit.ts` and the scene's `ContentScene.ts`)
un-rotate the balloon outline into the element's frame before fitting. The scene already rotates
the drawn text about its centre. E3 is built after G2 (#176), as D1 (a) decided: today the
export never sees the outline, so the editor and the export differ already (p27), and rotation
would widen that gap. There is no editor-only E3 before G2.

**Gate (E):** the sign case and sample222's tilted banner come out tilted in the editor and the
export; the 22 B pages and the six fixtures, rotated elements only, read beside Torii.

## Answers (owner, 2026-10-07)

- **D1: (a).** G2 is built before E3, so the export fits tilted text to the same outline as the
  editor.
- **D2: (b), with a warning.** A merge works like ordinary layer merging: the upper layer's
  text sits over the lower one, and the lower text is kept, hidden, in the merged layer. The merge
  says how many regions had text on both layers and that the lower text is now hidden. The only
  follow-up is *Delete hidden texts* for the merged layer; there is no swap and no join (owner,
  2026-10-07, asked: "in typical layer merging the upper layer's things go over the lower ones and
  the lower ones get hidden").
- **Undo of a merge follows F4:** it survives a save and a reload (the server's record of the last
  20 layer actions), not only until the page is saved.
- **D3: 20 layer actions per page.** Later, a setting in the environment for the depth, with a
  memory cap on what the stored rows may hold.
- **D4: on, with a switch,** once E0's numbers are in. The switch goes in System Settings (the
  OCR section), and its help text says that off sets every text level, as before.
- **D5: F3 and F4 now, E after.**
- **Page-project ZIPs go to version 3.** Version 2 is refused, as R7-D3 says. The release notes
  say so, and F3 ships a tool that converts a version 2 file to version 3 (a version 2 file has
  no groups, so only the version changes), so an old file can still be imported. This is the
  owner's one exception to the no-converter rule, recorded in the tracker's scope overrides.

## Decisions (as asked)

- **D1: G2 first?** The tracker's order is C + G, then F, then E. E3 changes the same fitter
  G2 does. Options:
  - (a) do G2 (#176/#177) before E3. **Recommended:** the export then fits rotated text to the same outline as the editor.
  - (b) E3 fits only the editor and leaves the export on the ellipse until G2. (Not chosen.)
- **D2: merging two text layers that both have text for one region.** It happens whenever a
  re-translation layer is merged into the original. Options:
  - (a) keep both, as Photoshop does: the page shows both texts until you delete one, and the merge
    dialog says how many regions have text on both layers;
  - (b) the upper layer's text wins, and the lower one is kept hidden in the merged layer.
  **Recommended: (b).** That is what you see before the merge, so the merge changes nothing on
  the page, and the lower text is one click away.
- **D3: undo depth.** 20 layer actions per page, no time limit. Say if you want more.
- **D4: E on by default?** **Recommended: on, with the switch,** once E0's numbers are in.
  13% of regions on half the pages change, so it is worth having on. If E0 shows too many wrong
  angles, ship it off and turn it on per series.
- **D5: F3 + F4 now, or after E?** They change no output. The re-run pile-up is the only
  pressing part, and a group (F3) alone fixes that. F4 could wait.
