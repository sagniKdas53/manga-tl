## Where things stand

**The geometry gate passes and Phase 1's founding assumption is validated.** CTD's `seg` head gives
a glyph-level mask: median component **194 px** against the ≤ 2,000 px gate (ours: **49,276 px**).
Balloon-outline damage 0.9 % against our 39.4 %.

**But 2026-08-27 measurement found two things the plan did not account for.**

1. **Per-region crops are the accuracy fix, not the cost fix** (Finding 6). They close sample106's
   gate failure decisively — 4,466 px median → 220 px — and tighten coverage on every page. They
   also cost **~1.4× a whole-page pass, not less.** A whole-page pass is a fixed 1024² regardless of
   page size, and our crops sum to *more* than that once the 64-px context pad is added. The plan's
   "cost then tracks text area, not page area" is wrong for our pages. Adopt for accuracy; the
   latency gate is still open.
2. **CTD trades artwork damage for residual text** (Finding 7). Ours leaves ~0 % residual ink by
   construction — an opaque slab cannot fail. CTD + TELEA leaves a median 6.1 %, and **9 of 21 pages
   are over 10 %, four over 27 %**. A median 98.7 % of what CTD misses is glyph ink rather than
   balloon outline — though that median hides a bimodal split, and on four pages the majority of
   the miss *is* outline, which CTD is right to skip.
   **Phase 1 needs an explicit recall-recovery step that it does not currently have.**

**And one cheap win** (Finding 8): the threshold should move **0.5 → 0.3**. Overall recall is nearly
threshold-independent (92.1 % → 87.7 % across the whole 0.3–0.7 range), but **light-on-dark recall
moves 26.6 points** over the same range — the polarity weakness is a confidence-calibration problem,
not a detection one, which is exactly what a threshold can fix. Outline-kill rises 1.6 % → 2.5 %,
still ~16× better than our 39.4 %.

sample136's 45.6 % recall is no longer unexplained-and-alone: sample93 (41.5 %) and sample128
(56.1 %) behave the same way. The shared property is dense text over busy artwork — *not* inverted
polarity, which the DARK group had already failed to support.

### Rebuilding the models from scratch

```
curl -L -o ctd.onnx https://github.com/zyddnys/manga-image-translator/releases/download/beta-0.3/comictextdetector.pt.onnx
# md5 165141f94293c24f5ed2074369d72a6a, 94,669,756 bytes
python3 extract.py     # needs `onnx`; writes models/ctd_seg_dyn.onnx
```
`extract.py` calls `onnx.utils.extract_model(..., ['images'], ['seg'])` then rewrites the input and
output spatial dims to `h`/`w`. `onnx` is not in the project venv — reinstall with
`pip install --target ./pylibs onnx`.

## Environment notes

- 4 cores / 19 GB. Worker capped at `cpus: "2.0"` / 4 GB (`docker-compose.yml:415`).
- CTD trimmed: ~77 s/page at 4 threads on a quiet box, 110–115 s under load. Expect roughly double
  at the worker's cap. **Timing runs need a quiet machine** — the first crop numbers had to be
  re-measured because shell work was competing for cores.
- Every inference logs `Expected shape from model of {1,1,1024,1024} does not match actual shape`.
  That is expected with dynamic input and is not an error. Filter with `grep -v onnxruntime`.
- Long runs need `PYTHONUNBUFFERED=1`, or a pipe through `tee`/`tail` hides all output until exit.
- `pkill -f <pattern>` kills its own wrapper shell when the pattern appears in the wrapper's command
  line. Use `for p in $(pgrep -f X); do kill $p; done` in a *separate* command — and note that this
  bit again today.
