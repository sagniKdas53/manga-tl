## Checkpoint 2 — current code and executable boundary reproductions

Detailed worker and canvas paths, test commands, and limits are in [worker-investigation.md](quality-evidence/worker-investigation.md) and [canvas-investigation.md](quality-evidence/canvas-investigation.md). The following findings come from current code and executable diagnostics, not old audit labels.

### Backend: edited page can remain permanently stale

`update_layer_element` receives a layer-element ID (`backend-rust/src/routes/layers.rs:116`) and calls `touch_page(&state.pool, id)` at line 212. `touch_page` uses that argument in `SELECT page_id FROM layers WHERE id = $1` (lines 103–110). A normal element ID is not its parent layer ID. The element saves, but the timestamp update affects no page; the dirty-page scanner has no new edit to render.

Reproduction: `.venv/bin/python docs/quality-evidence/backend-sync-repro.py`. It reads the actual update SQL and checks the actual caller from current source. Executing that SQL in isolated SQLite with distinct page/layer/element IDs updates **0 rows** for the current argument, versus **1 row** for the parent layer ID. It supplies a deterministic `now()`; this is an executable SQL/identity reproduction, **not** an Axum/PostgreSQL integration test. Results: [backend-sync-results.json](quality-evidence/backend-sync-results.json).

There is a second independent recovery problem: `process_pending_renders` selects pages where `last_edited_at > last_rendered_at`, then stamps `last_rendered_at = now()` as soon as `trigger_page_redo` accepts the job (`backend-rust/src/jobs/recovery.rs:150-197`). The diagnostic shows pending pages go **1 → 0 without a completion callback**. If that render never produces an artifact, the dirty predicate stops selecting it. A separate retry mechanism could still retry a job; this reproduction proves the dirty-page recovery predicate is prematurely cleared, not that every failed job is permanently lost. Completion also stamps wall-clock time (`coordinator.rs:2135-2141`), so edit revisions made during an in-flight render need an explicit revision contract.

GitNexus upstream snapshot: [backend-impact-snapshot.json](quality-evidence/backend-impact-snapshot.json). `touch_page` is **CRITICAL** (six direct layer-operation callers); `update_layer_element` is graph-LOW with no indexed callers (an HTTP boundary, not proof of no consumers); recovery is LOW with scheduler/main dependents. The user was warned of the shared-helper risk. No symbols were edited. Prefer fixing the incorrect caller with focused integration coverage; inspect layer deletion and other callers before changing the helper contract.

### Worker/backend: original composition is lost before text fitting

- OCR converts quadrilateral detections to axis-aligned min/max rectangles (`worker/src/worker/handlers/ocr.py:783-800`) and emitted regions set `rotation: 0.0` (e.g. lines 1243, 1310, 1395). Manual rotation support in the editor does not recover automatically discarded source angles.
- Grouping remains connected-component based. A synthetic adjacent chain reproduces one merged box; this establishes an algorithmic failure mechanism, not the exact detector output on the six source pages. Raw detector fragments and YOLO masks are missing from the saved projects.
- No-mask cleanup synthesizes padded covers (`ocr.py:320-357`). The render loop paints solid polygons, and for free text can also paint the layout rectangle (`render.py:1217-1243`). This active path has no glyph-mask clean-plate reconstruction. Reducing grouping errors alone will not restore textured backgrounds.
- The backend creates translated elements with `Comic Neue`, bold, and black/white contrast derived from the sampled background (`backend-rust/src/jobs/coordinator.rs:1998-2022`). That insert does not propagate source rotation or per-source outline color. All visible translations in the six saved projects use Comic Neue and rotation 0.
- Torii's saved metadata provides a concrete contrast: sample177 has 11 positioned elements with angles from -11.8° to +1°; sample222 has 15 elements, 13 fill colors, and angles from -15.3° to +12.4°. These are vendor output choices, not annotations of correct detection, translation, or style. They demonstrate a richer representation than one merged default-styled paragraph.
- The old free-text squaring algorithm is absent: `free_text_box` now retains height and bounds width growth (`coordinator.rs:1632-1663`). Do not reimplement that historical fix. Page-edge clamping and container ownership still need independent coverage.

Graph scope: [impact-snapshot.json](quality-evidence/impact-snapshot.json). `group_fragments` is LOW: direct caller `merge_ocr_regions`, downstream OCR handler participates in four graph traces. `text_box_for` is LOW: `handle_translation_callback` calls it, with three callback traces affected. Graph scores describe dependency scope, not visual risk: an OCR change can alter every later pixel even with one caller.

### Canvas/archive: inspect each boundary separately

- Ordinary fractional-rotation save DTO test passes (`cargo test --lib accepts_the_fractional_box_a_rotation_produces`). This checks parsing/rounding, not a browser-to-database round trip.
- Archive restore still uses `as_i64()` for width/height (`backend-rust/src/routes/page.rs:1950-1961`). The source-bound reproduction `node docs/quality-evidence/canvas-zip-fractional-repro.mjs` shows a JSON box 186.43×187.91 restores as the defaults 150×80, while rotation 12.5 survives. Imported projects must be tested independently of same-database editing; a region UUID alone is not a portable region definition.
