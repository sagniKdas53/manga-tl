## The rule (port it as it is)

`scripts/e0/angle_rule.py`, about 90 lines. For each region:
1. Take the OCR pieces from `ownershipProvenance` (either `fragments[].provenance` or the
   region's own provenance) and each piece's `sourceQuad`. A piece's direction is its quad's long
   edge.
2. A piece votes only if its long edge is at least 1.5 times its short edge (a single glyph has
   no direction).
3. A piece's angle is how far it is off the nearest axis (±45°). If any voter is more than 35° off,
   every piece is read as a line along its long edge instead (±90°). That is the near-45° fix (#265).
4. Directions wrap at ±90°, so they are unwrapped around the voter closest to all the others
   (CodeRabbit on #255).
5. If three or more voters disagree by more than 6°, the one farthest from the length-weighted
   median is dropped, once (#266). If they still disagree, the region stays level.
6. The angle is the length-weighted mean. Under 5° it stays level.

Settled numbers: dead band 5°, a piece votes from 1.5 line-thicknesses, agreement 6°. Positive
is clockwise on the page (y runs down), the same as `rotation` in the editor and the scene.

Port its tests too. Build them from the cases in the scripts: −89°/+89° agree and turn −90°;
44°/46° turn +45°; a single square piece stays level; one stray piece among three is dropped.

## What to build

### Worker (submodule `worker/`, its own PR, then a parent pin)

- **One pass at the end**, not six edits. `handlers/ocr.py` writes `"rotation": 0.0` at five
  places (L1635, L1666, L1718, L1750, L1810), and `services/merge_regions.py` at one (L243). Leave
  those. Before `callback_payload` is built (`handlers/ocr.py` ~L1959), run the rule over
  `ordered_regions` and set each region's `rotation`.
- **The box goes along the text.** A turned region's `x/y/width/height` today is the level box
  around tilted text, which is too tall and too wide. For a turned region, un-rotate the pieces'
  quads by the angle about their centre and take that box. The result is a box of the same centre,
  rotated by `rotation` about its centre, which is how the editor (`rectToPolygon`,
  `frontend/src/utils/polygonUtils.ts`) and the scene (`ContentScene.ts` L344) both draw it.
  Leave `bubble*`, `safeText*` and `maskPolygon` alone: they are page-space shapes, and cleanup
  works from the glyph mask.
- **Settings.** The job carries `ocrTextAngle` (true/false). The dead band stays a worker
  constant (5°). A job with no value (queued before the deploy) uses the worker env
  `OCR_TEXT_ANGLE`, default on. Follow `merge_threshold_for` (`handlers/ocr.py` L95) for the shape.
- **Capture.** Add the angle and the reason ("turned", "dead band", "pieces disagree", "no long
  piece") to the region's `ownershipProvenance`, so *Show debug → OCR fragments* can show why a
  region turned or didn't.

### Backend (`backend-rust/`)

- **Regions already store it.** The OCR callback writes `rotation` (`jobs/coordinator.rs` L1675,
  L1690). Nothing to change there.
- **Text elements don't copy it.** Copy the region's `rotation` into the new element at the three
  inserts that make text from a region: `coordinator.rs` L1807 (the OCR layer), L2566 and L2939
  (the translation layer). Each insert's column list has no `rotation` today.
- **Setting plumbing**, the same path as `ocrMergeThreshold`: `settings.rs` (global, key
  `ocrTextAngle`, default true), `models.rs` and `routes/series.rs` (series and chapter override,
  NULL = use the global), the job payload in `coordinator.rs` ~L952 (chapter → series → global),
  `database/init.sql` plus an upgrade SQL file (two nullable boolean columns), and a hand edit of
  `golden-openapi.json` (it is a frozen file; nothing generates it).
- **A hand merge** (`routes/page.rs` ~L2020–L2140, `union_box`) keeps the survivor's `rotation`
  today but builds a level union box. Rule: if every merged region has the same angle within 6°,
  keep the survivor's angle and build the box along it; otherwise set 0. Don't re-run the full
  rule in Rust.
- **#268 (small, separate).** A duplicate upload copies regions without `ownership_provenance`.
  The angle survives the copy (`rotation` is copied). Fix it separately; E2 doesn't need it.

### Frontend

## What it changes, and what it doesn't

- **Changes:** pages OCR'd after the deploy, or after *Redo OCR*. A page keeps its level text until
  then. Saving the setting must not dirty any page (AUDIT-B27).
- **Measured:** on the 13 test pages, 39 of 66 Torii-tilted boxes turn within 5° of Torii. On 35
  pages that overlap Torii's corpus, there are 6 false turns from two regions. One is a junk
  over-merge on sample218. The other is sample104's book-cover title (−15.6°, where Torii's box
  says +4°; the owner judges). On the owner's Rotate set (Free ch. 7, 26 pages), the turns match
  the art, and the controls stay level.
- **Korean stays level.** Korean OCR (PP-OCRv5) gives one piece per paragraph, so there is no line
  to measure. That is today's behaviour, not a regression.
- **Known, not fixed by E2:**
  - Rotate p8: one diagonal sign is two overlapping regions (grouping, #231). Both turn, and they
    still overlap.
  - Junk regions get an angle (#267). Their translations are usually empty, so nothing is drawn.
  - Vertical columns tilted more than 35° would read about 90° off (the near-45° fix assumes
    horizontal lines). None was seen on the test sets.
  - Text OCR never found has nothing to turn (sample104's sash, #245).
- **Not in E2:** text fitting a rotated balloon's outline is E3, after G2 (#176/#177).

## Gate

On the F test stack (chrome-box, `manga-f-20261007`), after deploying the worker and backend:
1. *Redo OCR* on the owner's Rotate set (Free ch. 7: p1–p26, but not p22 and p23, which are
   copies; use B #230 test (ja) p9 and p19 for those) and on the E rotation test series. Rotate
   p13–p15 are controls: nothing turns.
2. Export each region's `rotation` and compare it with `scripts/e0/check_rotate.py` and
   `check_test_pages.py` run on the same regions. The worker and the script must agree to 0.1°.
3. Open p5, p7, p8 and p12 in the editor and in the export: the text is tilted the same way in
   both, and the box is not taller than the text.
4. The switch off (global, then one series override) and *Redo OCR*: every region on that page
   is level again.
5. Re-render, not re-OCR, the six fixtures and check the draw lists are unchanged. E2 only acts
   at OCR time. Re-renders queue paid QA unless a page is hand-edited, so use draw-list dry runs.

The owner tests in the editor themselves. Don't re-run pages for them beyond the gate.
