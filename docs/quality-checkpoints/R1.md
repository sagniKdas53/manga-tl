## What changed

**Backend** (`backend-rust/`)
- New `page_scene_builder.rs`: derives a valid `page-scene/v1` logical scene from `ocr_regions` + visible translation/sfx `layer_elements`; rasterizes each element's legacy mask polygon into a content-addressed cleanup patch + mask PNG under `scene-assets/<page>/<sha256>.png`; writes the snapshot, owners and assets and advances the page revision in the caller's transaction (`snapshot_pipeline_scene`); `snapshot_render_payload` for synchronous callers. A faithful projection of today's pixels on purpose — the patch is the same flat fill Pillow painted — so R4 can show "no regression" on the cutover itself.
- `coordinator.rs`: translation callback and QA final pass snapshot the page and queue an immutable render (`enqueue_snapshot_render`) instead of a bare Pillow `render` job. `prepare_hybrid_qa` returns the render payload. OCR callback replaces the page's regions (`purge_page_regions`) — the Java port kept every pass's rows, which is what made `sample61` 214 rows / 63 boxes / US$0.25. Render callback stores the renderer's layout diagnostics in the ledger.
- `recovery.rs`: `enqueue_current_snapshot_render` is public, carries job flags and presigned `renderAssetUrls`. The debounce poller builds a snapshot for a page that needs a render and has none at its current revision (editor edits rely on this), with a five-minute backoff for pages whose scene cannot be built. This is the loop that logged 3,130 lines and queued nothing.
- `page_scene_builder.rs` reads through the caller's transaction (found by live run 1, below).
- `routes/internal.rs`: render callback accepts a JSON body (the browser callback carries an integer revision and a diagnostics array; the old `HashMap<String, String>` would have rejected it); `qa-hybrid-prepare` returns the payload or 204.

**Worker** (`worker/`)
- `handlers/render.py`: 1,500 → 70 lines. Scene in, browser out, callback with revision/digest/png sha/diagnostics. A job without `logicalScene` raises `RenderJobError`; no Pillow fallback. Tests for Pillow typography (`test_render_extra`, `test_typesetting`, `test_render_layer_filtering`, the Pillow half of `test_render_and_qa`) deleted with it; `pyphen` dropped from requirements.
- `page_scene_renderer.py`: downloads each cleanup patch by presigned URL, verifies sha256 + byte length against the scene's asset record, embeds as a data URL (the renderer refuses external hrefs — E04's transport passed URLs straight through and would have been rejected); unreachable/rejecting renderer fails the job with the reason; returns the result.
- `handlers/qa.py`: hybrid mode renders the prepare payload through the browser instead of calling Pillow inline.

**Frontend**: `Export Page (PNG)` downloads `GET /api/pages/{id}/rendered` (the current artifact) and reports pending/failed instead of drawing a Canvas. The ZIP export still draws layer PNGs on Canvas — that is I06, not R1.

**Compose**: worker no longer `depends_on: page-renderer` (both files). Capture harness pinned to `deepseek/deepseek-v4-pro` (user decision 1).

## What R1 leaves behind

- Pillow typography is gone from the worker; there is no render fallback. A missing `page-renderer` fails render jobs with the reason in the job table and does not stop OCR/translation (compose `depends_on` relaxed).
- The debounce poller now snapshots and queues; the 3,130-line livelock is gone from the logs (`stack.log` has no `[Render] … skipped`).
- Not done here, on purpose: patch shape (R2), glyph masks (R3), ZIP export still draws on Canvas (I06).
