# F04: owner-aware OCR integration

Status: **REVIEW** — normal-runtime integration is complete; the fresh six-page G5 run is blocked before stack readiness by unrelated frontend TypeScript build errors.

## Change

`process_ocr` now performs F01 decisions during ordinary runtime; no `OCR_CAPTURE_DIR` is required.

- Inside a YOLO detector container, every graph component receives stable fragment IDs, source-space quads, its exact candidate polygon, and unit source scale. An unknown multi-fragment decision vetoes only that join; an assigned decision remains attached to every member's `ownershipProvenance`.
- Unmatched and no-YOLO fallback components also receive F01 decisions. With no validated detector container, multi-fragment ownership remains explicitly `unknown`; current observation grouping is retained rather than silently promoted to a resolved owner or converted into a blanket split.
- Merged output retains member-level decisions under `ownershipProvenance.fragments`; the existing Rust OCR callback persists that JSONB boundary. Decisions and F03 review container states remain provenance only and grant neither `replace` policy nor cleanup authority.

Missing source style is no longer a mandatory veto under F01. It remains `unknown` evidence; geometry, container identity, and source scale control a multi-fragment assignment.
