# F04: owner-aware OCR integration

Status: **REVIEW** — normal-runtime integration is complete. G5 capture started after the isolated stack became buildable, but is paused on the user's reported empty/layerless export artifact.

## Change

`process_ocr` now performs F01 decisions during ordinary runtime; no `OCR_CAPTURE_DIR` is required.

- Inside a YOLO detector container, every graph component receives stable fragment IDs, source-space quads, its exact candidate polygon, and unit source scale. An unknown multi-fragment decision vetoes only that join; an assigned decision remains attached to every member's `ownershipProvenance`.
- Unmatched and no-YOLO fallback components also receive F01 decisions. With no validated detector container, multi-fragment ownership remains explicitly `unknown`; current observation grouping is retained rather than silently promoted to a resolved owner or converted into a blanket split.
- Merged output retains member-level decisions under `ownershipProvenance.fragments`; the existing Rust OCR callback persists that JSONB boundary. Decisions and F03 review container states remain provenance only and grant neither `replace` policy nor cleanup authority.

Missing source style is no longer a mandatory veto under F01. It remains `unknown` evidence; geometry, container identity, and source scale control a multi-fragment assignment.

## Root cause and correction

The live worker interpreted every unreviewed M3 policy record as a reason to skip the provider target. Fresh OCR regions consequently never reached the translation callback, and the backend correctly had no entries from which to create translation-layer elements. This was a scheduling regression, not an authorization decision.

The correction restores the live path the editor requires: OCR candidates, including unreviewed dialogue and candidate SFX, reach translation and then visual QA; QA can issue `reject_sfx` and hide only the rejected element before the final legacy render/export. Explicit `preserve` and `explain` user overrides still omit the region from provider work and the callback. M3 policy metadata remains available for the later canonical-scene cleanup boundary; it no longer suppresses this existing pipeline.

The immutable `/rendered` endpoint remains intentionally unavailable for pages without a canonical page-scene snapshot and render ledger. It is not the source of the zero-object layer; the Reader now displays that endpoint failure instead of silently logging it. The current live pipeline's `Export Page (PNG)` path is the relevant corrected export surface until the planned M8 cutover.
