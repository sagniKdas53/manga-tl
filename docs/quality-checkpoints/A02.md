# A02 — OCR/grouping capture and replay

Status: `REVIEW`

## Reproduction

The current worker seams are `parse_paddle_ocr_results` / `parse_rapid_ocr_results` followed by
`merge_ocr_regions` and `group_fragments`. A02 keeps those algorithms unchanged and observes their
stage values at the grouping boundary. The worker GitNexus index resolved `group_fragments` with
LOW upstream risk (one direct caller and one OCR process); no existing production symbol was
edited.

## Change

`worker/src/worker/services/ocr_capture.py` adds a JSON capture format, `capture_ocr_grouping`,
file read/write, and `replay_twice`. A capture persists:

- source ID and digest;
- raw oriented quads and the OCR-to-source scale transform;
- detector masks;
- recognition text and confidence;
- normalized regions used by grouping;
- grouping configuration and grouping edges;
- stable final owner IDs with their fragment IDs;
- per-stage path provenance (`live`, `cached`, or `stubbed`).

Fragment IDs are SHA-256-derived from source ID, input index, raw quad, and region. Owner IDs are
derived from their member fragment IDs, so replay does not depend on process ordering or runtime
object identity. `worker/tests/test_ocr_capture.py` writes and reloads a capture, then replays it
twice and compares IDs, geometry, edges, and owners.

For the focused fixture, OCR and grouping are recorded as `live` seam values and detector masks as
`cached`; no native OCR/model call is made by the test. The harness accepts `stubbed` explicitly
for unavailable stages, so later A03 runs can identify those paths rather than silently treating
archived output as fresh OCR.
