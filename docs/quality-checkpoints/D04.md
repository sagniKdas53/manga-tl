# D04 — Policy scheduling guards

## Status

**Complete — 2026-09-14.**

## Decision

`worker.handlers.qa._translation_qa_regions` recomputes the frozen D02 policy at every per-region QA boundary. Only effective `replace` regions are supplied as LLM/VLM metadata and only those IDs survive QA-result sanitization. The visual VLM still receives the complete original/rendered page image, so preserved source SFX remain visible for page-wide visual assessment without becoming per-region translation verdict targets.

`process_translation` already constructs initial chunks, batch retries, and individual fallbacks solely from `unmatched_regions`. D03's policy filter makes skipped regions unavailable to all three paths; no failure state is fabricated for a policy skip.

## Regression evidence

- `test_policy_skipped_region_never_reaches_translation_retry_or_fallback` forces the selected dialogue through a failed batch and failed batch retry. Both batches and the individual fallback contain only `replace-dialogue`; the review SFX is reported exclusively in `policy.skipped`.
- `test_policy_skipped_regions_never_enter_per_region_translation_qa` proves an LLM QA provider prompt excludes the review SFX ID and raw text, and that a malicious QA result naming it is dropped before callback.
- `test_translation_qa_regions_selects_only_effective_replace` covers review, explicit preserve, and explicit replace decisions.
