# C03: immutable render-job scheduling

Status: **DONE**.

`process_pending_renders` now schedules only the immutable `page_scene_snapshots` row matching a page's current revision. It stores `(page_id, page_revision, logical_scene_sha256)` in `page_render_jobs` before queueing the worker job, carries the exact logical scene/document and digest in the job payload, and uses that ledger to deduplicate queued/running/succeeded work. A page whose current revision has no snapshot remains pending; it is never rendered from mutable rows.

The generic queue builder accepts an explicitly reserved payload `jobId`, allowing the page-render ledger and `jobs` row to share one ID. If a process dies after reserving the ledger but before creating the generic job row, the next debounce scan reuses the reserved ID rather than creating a duplicate ledger row. Enqueue does not set `last_rendered_at`.

Focused isolated-stack gate:

```text
backend-rust$ ./scripts/test-env.sh run cargo test --test jobs_endpoints recovery_reset_stale_and_debounced_render
...
test recovery_reset_stale_and_debounced_render ... ok
```

The regression adds immutable snapshots for revisions 0 and 1. It proves repeated scans queue revision 0 once, then an edit while that render remains queued produces a distinct revision-1 ledger entry. Existing failure-cooldown behavior remains covered. `cargo fmt --check` passed and test services were removed.
