# D03a — restore live translation and QA scheduling

## Status

**DONE — 2026-09-16.**

## Problem

A fresh `sample177` run created an OCR layer with four elements and a Translation layer with zero elements. The worker had applied the new canonical-scene policy's default `review` action as a provider-target veto. Because every newly classified region is `review` without an explicit override, the translation callback received no entries and the backend had nothing from which to create translation-layer elements.

That contradicts the established live editor flow: OCR candidates appear first; translated elements appear next; visual QA then rejects/hides SFX or bad OCR before the final legacy render/export.

## Correction

- `worker.handlers.translation.process_translation` retains policy metadata but sends unreviewed dialogue and candidate SFX through translation. Only explicit `preserve` and `explain` overrides omit a region from provider work and the legacy callback.
- `worker.handlers.qa._translation_qa_regions` selects successful translation-layer elements rather than effective canonical-scene `replace` actions. QA can therefore issue `reject_sfx` and hide only that element.
- `Reader.handleExportRenderedPng` now surfaces the immutable-artifact endpoint failure instead of silently logging it. The current page-scene artifact endpoint remains separate from the legacy `Export Page (PNG)` surface used by this live pipeline before M8 cutover.

This does not authorize canonical-scene cleanup or automatic replacement there. Canonical-scene policy remains fail-closed; the correction is limited to the existing translation/QA/editor-layer pipeline.

## Impact

- `process_translation` (`manga-tl-worker`): **LOW**, zero graph-resolved upstream callers/processes.
- `_translation_qa_regions` (`manga-tl-worker`): **HIGH**; direct consumers are LLM, VLM, and hybrid QA flows, with `process_qa` at depth two. The user was warned before the edit.
- `handleExportRenderedPng` (`manga-library`): **LOW**, zero graph-resolved upstream callers/processes.
