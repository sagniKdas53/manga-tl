# D05 — Policy contract validation

## Status

**Complete — 2026-09-14.**

## Decision

Automatic replacement authorization is now a shared semantic gate within each contract consumer:

- Rust `validate_replacement_request` is called for every cleanup artifact and every `automatic_text` object before the scene is persisted by `PUT /api/pages/{pageId}/scene`.
- Worker `_validate_replacement_request` applies the identical effective-`replace` and non-blank-automatic-text rule before a render request is admitted.
- The worker now rejects an empty-string `user_override` rather than treating it as absent. This matches the schema and Rust validator: only `null` means no override.

Manual text and manual cleanup remain outside the automatic-replacement gate. No fallback creates a blank automatic object.

## Tamper regression

The shared invalid fixture set now contains `invalid-blank-user-override`, in addition to contradictory preserve/cleanup and blank automatic-text cases. The JavaScript contract runner, Rust API validator, and worker validator all reject every invalid fixture.

## Impact

GitNexus impact was **LOW**:

- Rust `validate_page_scene`: two direct callers — `put_page_scene` and its shared-fixture test; one API error flow.
- Worker `validate_page_scene`: one direct caller — `PageSceneRenderRequest.validate_scene_artifact`; no indexed execution flow.
