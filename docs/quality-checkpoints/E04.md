# E04: immutable browser render transport

Status: **DONE**.

The worker routes every queued job carrying `logicalScene` to `worker.page_scene_renderer.render_page_scene`; legacy jobs alone retain `render_image_core`. The high-risk `render_image_core` function was not changed: GitNexus reported HIGH upstream impact through `process_render` and `_process_qa_hybrid`, affecting three process functions. `process_render` was LOW risk with no graph-resolved upstream callers. `PageSceneRenderRequest` was LOW risk with one importer. The backend's existing C03 dispatcher already supplies the exact queued `pageRevision`, `logicalSceneSha256`, and immutable `logicalScene`; C04 owns the revision/digest callback ledger.

The adapter validates the page-scene/v1 logical artifact and verifies that its canonical digest and revision equal the queued values before retrieving source bytes. It retrieves no mutable layer geometry. It verifies the retrieved source SHA-256 against the queued scene, accepts cleanup URLs only as job-scoped immutable asset references, invokes the pinned renderer HTTP endpoint, verifies response revision/digest and PNG SHA-256, then writes the staging object C04 consumes. A missing renderer URL, cleanup asset, mismatched source, identity mismatch, timeout, or renderer error raises normally; RQ therefore follows the existing retry/failure semantics. New-format jobs cannot fall back to Pillow typography.
