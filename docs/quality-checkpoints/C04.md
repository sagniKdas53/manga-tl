# C04: immutable render callback completion

Status: **DONE**.

The render callback now resolves a page-render ledger row by its exact job ID, reads the worker's rendered PNG, hashes it, and copies the bytes into an append-only revision/digest/hash object path. In one database transaction it claims the callback, records the output hash/path, marks the ledger job `succeeded`, and advances `pages.current_render_job_id` and `last_rendered_at` only when that job's `(page_id, page_revision, logical_scene_sha256)` still equals the page's current immutable snapshot. A valid old callback retains its own output but cannot mark the newer page current; duplicate deliveries make no second change.

`page_render_jobs.rendered_png_storage_path` stores the immutable result path. `pages.current_render_job_id` is the current-artifact pointer and has an `ON DELETE SET NULL` foreign key. The additive migration and fresh `database/init.sql` both install these fields. Render status patches mirror `PENDING`, `PROCESSING`, and `FAILED` into the ledger; a worker `COMPLETED` status is intentionally insufficient to mark a result successful, because only the callback attests the immutable artifact.
