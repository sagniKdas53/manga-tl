# C01: page freshness after element edit

Status: **READY** — B05 and G1 are complete; the defect has been reproduced against the live isolated backend and the first fix is bounded to the incorrect caller.

Date / app head / worker head / corpus head: 2026-09-14 / `60c3cfc` / `5a97868` / `27de7499f0c4c142763116bfcbcfd0afd9709cbf`.

## Reproduction

An isolated PostgreSQL/Valkey/MinIO stack and backend were started. The probe created a series, chapter, uploaded page, translation layer, and text element through the real HTTP API. After resetting that page's `last_edited_at` to `NULL`, it sent:

```text
PUT /tlhub/api/layer-elements/c325474d-d3f8-44d9-9a32-791d298f0e43
{"text":"after"}
→ 200, updatedText="after"

SELECT COALESCE(last_edited_at::text, 'NULL') FROM pages
WHERE id = '93a42c9e-f33c-4cd7-a3cc-2b9610552388'
→ NULL
```

The route therefore reports a successful element mutation while leaving its owning page ineligible for the existing timestamp-based render scan.

## Root cause and safe change

`update_layer_element` receives an **element** UUID, then calls `touch_page(&state.pool, id)`. `touch_page` expects a **layer** UUID and resolves the page through `layers.id`; no matching layer exists for an ordinary element UUID, so the update affects zero page rows. The handler already has the correct `updated.layer_id` from `RETURNING *`.

GitNexus upstream impact:

- `update_layer_element`: **LOW**, zero direct callers/processes.
- `touch_page`: **CRITICAL**, six direct callers across six flows (`create_page_layer`, `create_image_layer`, `delete_layer`, `update_layer`, `create_layer_element`, and `update_layer_element`).

The change must be only `touch_page(&state.pool, updated.layer_id)`. Do not change `touch_page` itself.

The regression test must seed page A/layer A/element X plus a distinct page B/layer B whose layer UUID deliberately equals X's element UUID (separate tables permit this). Before the edit, reset both timestamps. The current bug marks B; the corrected handler marks only A. This proves both the positive owner relation and the wrong-ID exclusion instead of merely asserting that some page timestamp changed.

No production code has changed in this packet.
