# F02: bounded graph components and owner vetoes

Status: **DONE**.

## Change

`GroupingConfig.component_max_members` is an opt-in full-component limit. `GroupingContext.owner_veto` is an opt-in callback evaluated only after connected-component traversal. A non-null veto reason or component over the configured cap splits that entire component into singleton candidates.

This preserves the frozen default: both fields are off, so `group_fragments` remains legacy-equivalent until F04 supplies an owner-aware context. The boundary cannot create a merge. It sees the complete transitive component, so a middle fragment cannot turn an F01 unknown owner decision back into an A–B–C merge. It deliberately does not use panels, conversations, or reading order.
