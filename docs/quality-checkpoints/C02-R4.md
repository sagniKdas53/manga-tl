# C02-R4: transactional archive replacement

Status: **DONE**.

## Change

Project archive restoration now runs layer-edit-history deletion, layer/element replacement, optional `pages.image_id` source swap, and `scene_revision` advancement in one caller-owned PostgreSQL transaction. Any database failure leaves the prior editable page and its source assignment intact. Image-object upload and image-row creation occur before that transaction; they may leave an unreferenced immutable object if the later page replacement rolls back, but cannot expose a partially replaced page.

`restore_project_layers` and `clear_page_layers` no longer suppress database failures. Both the upload archive route and chapter import route use the same transaction helper. Cover recalculation remains post-commit because it reads the committed current source.

## Focused gate

```text
backend-rust$ ./scripts/test-env.sh run cargo test --test import_export_endpoints image_archive_upload_and_project_restore
...
test image_archive_upload_and_project_restore ... ok
```

The isolated PostgreSQL/Valkey/MinIO test imports a schema-version-1 project, then restores a project with a different original image into the occupied slot through the upload route. It proves the source image UUID changes, exactly one replacement element remains, and the page revision advances from 1 to 2. Unsupported schema version 2 is rejected before mutation. `cargo fmt --check` passed and the temporary services were removed.
