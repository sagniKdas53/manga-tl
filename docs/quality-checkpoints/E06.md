# E06: assembled renderer capacity

Status: **DONE**.

The repaired E05 image builds the static browser bundle in a repository-root build stage, resolves canonical scene font IDs to registered browser families, and copies the bundle to the runtime image. The resulting `manga-page-renderer:e05` image is `sha256:7c604f880c6b98cee3cba273e65174aebfab2501bd245cbbc7d138be9e754bf0`; it uses the pinned amd64 Playwright image and Comic Neue file hash recorded in E05.

## Measured container

`docker run --memory 2g --cpus 1.0` with one reusable browser context. The renderer returned source-sized lossless PNGs and no layout diagnostics:

| input | dimensions | elapsed | sampled peak RSS | PNG SHA-256 |
| --- | ---: | ---: | ---: | --- |
| ordinary synthetic scene | 320×180 | 625 ms | 135 MiB | `ab287e7fd21b573d8114162a7b03464d254d62a06ae23fcd8599df12fee53b8b` |
| `sample93` cold | 6764×4961 | 28,408 ms | 658 MiB | `ebb71422cf7c471697d12bdb4ee2310335aecbe25ab918155f3e54bc9089101c` |
| `sample93` warm | 6764×4961 | 28,286 ms | 824 MiB | same |

824 MiB is below the tracker’s 80%-of-2-GiB headroom threshold (1,638 MiB). This is a one-context, one-CPU local measurement, not a throughput or speedup claim. Cold/warm timings are effectively equal for this source; no higher concurrency is enabled.

A large render was held in the sole context while a second ordinary request arrived. The second received HTTP 400 with `renderer context capacity is exhausted`; it did not queue silently, downsample, or use a Pillow fallback. The full retained machine-readable record is [evidence.json](../quality-runs/e06-20260915-renderer-capacity/evidence.json).
