# A01 — quality-run preflight

Status: `REVIEW` implementation evidence; G0 remains blocked until fresh six-page baselines exist.

## Reproduction and change

The repository had a backend integration-test recipe (`backend-rust/scripts/test-deps.yml`) and
`backend-rust/scripts/test-env.sh`, but no quality-run command that inventories the three checkout
heads and runtime hardware or verifies all required services before a run. The existing development
Compose file uses persistent named volumes and is therefore unsuitable as a test target.

Added:

- `scripts/quality-test-deps.yml`: Postgres, Valkey and MinIO on dedicated localhost ports
  `55590`, `56490`, and `19190`, with tmpfs data and no production network, volume, or container
  names.
- `scripts/quality_preflight.py`: validates the isolated Compose configuration, records app,
  worker, and corpus heads, model/font artifact SHA-256 values, CPU/memory/GPU information, starts
  the isolated services, inserts and reads a DB sentinel, checks Redis with an expiring sentinel,
  checks MinIO health, and fails nonzero on any unavailable dependency. It tears down the isolated
  project by default; `--keep-up` is available when the next test command needs the services.

The script reads no production credentials and its only database write is to the tmpfs-backed
`quality_test` database in the dedicated Compose project. It does not run `database/init.sql` or
connect to the serving Compose project.

## Validation evidence

Commands run from the repository root:

```text
python3 -m py_compile scripts/quality_preflight.py
docker compose -f scripts/quality-test-deps.yml config
python3 scripts/quality_preflight.py --report docs/quality-checkpoints/A01-preflight.json
```

`py_compile` passed. Compose config validation passed. The live preflight was attempted and is
recorded in `A01-preflight.json`; this run passed with the isolated DB, Redis, and MinIO health
checks. If Docker images or the daemon are unavailable, the report keeps `startup_error` and the
command returns nonzero. A successful run prints:
`quality preflight: PASS (isolated DB sentinel, Redis, and storage verified)`.

GitNexus impact was queried for the new script path and returned `Target not found`, zero impacted
symbols, and `UNKNOWN` risk because the new file is not in the current index. No existing symbol
was edited.

The report intentionally records partial failures rather than treating an early service failure
as an executed quality test. It contains no secret values.

## Limitations / next gate

This packet proves service isolation and runtime provenance only. It does not install the full
application schema, run the backend/worker, or produce fresh OCR/translation/render baselines.
Those are required by A01's G0 gate and remain coordinator work after this checkpoint.

The inventory currently contains two pinned YOLO model files and no font files under the scanned
repository roots. The absence of font artifacts is recorded as an environment finding and does
not satisfy the eventual effective-font provenance requirement.
