# H01a: basic ownership feature provenance

Status: **DONE**.

## Implemented boundary

`worker.services.ownership_features` now creates deterministic fragment IDs, source quads, source-space bounds, major-axis angle, and declared-style-or-unknown provenance. `OcrCapture.fragment_features` retains the same records and its replayed fragment IDs match them.

A user-authorized nullable `ocr_regions.ownership_provenance jsonb` migration is added. The Rust OCR callback accepts `ownershipProvenance` without exposing it in the public frontend `OcrRegion` type; GitNexus showed that public type has HIGH fan-out, so H01a deliberately avoids a UI/API contract expansion.

The YOLO raw-fragment route now creates source-linked provenance without requiring `OCR_CAPTURE_DIR`; `merge_ocr_regions` preserves it under final-region `ownershipProvenance.fragments`, with explicit container resolution. This adds no cleanup authorization and does not enable F01 owner vetoes.

## Completion

The non-YOLO/legacy OCR route also retains source-linked fragment provenance. The final acceptance trace now executes the actual internal OCR callback through an isolated PostgreSQL, Valkey, and MinIO stack: a worker-shaped `ownershipProvenance` object is accepted at `/tlhub/api/internal/jobs/callback/ocr`, then selected directly from `ocr_regions.ownership_provenance`. It preserves the fragment ID, source quad, nullable source style, and explicit `styleProvenance: "unknown"`.
