# C05: current immutable artifact reads

Status: **DONE**.

Every page-render reader now resolves the page's current immutable scene revision, rather than probing `rendered/{imageId}.png` or falling back to an original upload:

- `page_scene::current_render_artifact` returns `Ready`, `Pending`, or `Failed` only after it verifies the selected ledger row has the current page revision and current logical-scene digest.
- `GET /api/pages/{pageId}/rendered` streams that revision-specific object only for `Ready`; current `pending` and `failed` states return `409 Conflict` with `{ status, revision }`. It never returns an old artifact or original bytes.
- `GET /api/chapters/{chapterId}/pages` exposes `renderStatus`, `renderRevision`, and a revision/digest URL only when the current artifact is ready. `lastRenderedAt` is null for pending/failed pages. The image-level mutable rendered-thumbnail URL is deliberately null, so a grid cannot label it as current.
- Chapter exports package only ready immutable objects. A pending or failed current revision fails the export with a concrete page/revision diagnostic; it never packages an old result or the original upload. Export metadata includes the selected revision, status, and output digest, so its cache identity changes with output lifecycle state.
