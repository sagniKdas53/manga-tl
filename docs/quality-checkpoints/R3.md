# R3 — glyph-mask cleanup: the six-fixture gate, and why it is not passed

Status: **NOT PASSED** (2026-09-21) — quality is measured and mostly on target; time is not. Five of six fixtures were scored live through `docker compose up`; `sample61` exceeded the harness's 30-minute page window on the OCR stage alone, and every fixture's OCR stage is 1.5–8× slower than R2's whole pipeline because R3's cleanup runs inline, per region, twice, at native crop resolution. The measurements below are the input to the phase-separation design (tracker, R3 addenda 2026-09-21). R3a–e (the data path, worker → backend → scene) are done; R3f/R3g wait on this.

Reading it:

- **Region geometry is identical to R2 on every page** (counts, distinct rows, largest region, matches). Cleanup does not touch boxes, and the cap did not change what CTD found enough to move any region-level number.
- **Outside-bbox pixels are unchanged** (±0.02 on every page except sample99, which improved). Nothing is painted outside a region.
- **sample177 improved on both R2 flags** (flattened 3.55 → 2.80, hidden layers 2 → 0) and sample222's flattened share fell 5.85 → 5.30 — still over the 5 % wipe line, but that is R2's known "two huge regions" case, not a cleanup regression.
- **sample93 and sample83 now erase text that R2 left in place.** R2 painted no plate on those busy grounds (0.09 % / 0.16 % flattened — the source strokes stayed under a halo). R3's reconstruction erases the glyphs and lands at 3.17 % / 3.88 % flattened, against Torii's own 3.42 % / 2.78 %. The `FLATTEN-REGRESS` flag is measured against R2, so it fires; measured against the reference the pages are now doing what R3 set out to do. Whether the reconstructed pixels *look* right is a canvas judgement the scorer cannot make ([canvas is the judged surface](../output-quality-implementation-tracker.md)); the exports are in the run directories for that review.

### Where the cleanup time goes — sample61, all 63 regions

```
[OCR] stage timings: total=1245.9s | fetch=0.0s page-ocr=202.9s text-containers=0.3s yolo=0.7s
      regions=1041.8s order+payload=0.0s callback=0.1s cleanup=1038.0s/63 cleanup-upload=2.7s/63
```

| step | seconds | share of job |
| --- | --- | --- |
| CTD call 1 (glyph mask) | 519 | 42 % |
| CTD call 2 (residual-ink recheck on the reconstruction) | **514** | **41 %** |
| inpainting (62 TELEA, 1 AOT) | 5 | 0.4 % |
| PNG encode + MinIO upload | 2.7 | 0.2 % |
| PaddleOCR (170 recognised lines) | 203 | 16 % |

The recheck's verdict on those 514 seconds: maximum residual ink 3.3 %, no region over 5 %, none rejected. On sample93 (11 regions, 1010 s of cleanup): maximum 1.5 %, none rejected. The recheck re-runs the most expensive model on a reconstruction that took 5 s in total to produce, and on these six pages it never changed an outcome.

Per-region cost is set by the crop, not the text. CTD costs ~70–80 µs per fed pixel on this host on every call (the `[CTD] crop → fed … us/px` line shows it on every call of the run). A 14×9 px fragment on sample61 becomes a 142×137 crop (64 px context pad) and costs 5.4 s for a 1 KB patch; on sample93 every region of a 6764 px-wide page lands at or near the 1024 cap (`crop 2585x2904 … ctd=74.4s … recheck=91.1s`), 92 s per region. The whole page at 1024 — what PaddleOCR is given — is 1.05 MP and one call (~87 s measured in isolation, tracker addendum). The 17-region page from the user's own stack feeds CTD 11.4 MP per page today; that arithmetic is the tracker's.

### Two other clocks, visible for the first time

- **Translation is mostly reasoning.** The new `reasoning=` token line: sample61, 7 chunks, 19,838 of 26,717 output tokens were `deepseek-v4-pro` reasoning (74 %), at ~40 tok/s — about 8 of the 14 minutes. sample99: 81 %. All `finish=stop`, so the old log would have called these healthy; the user's explicit page earlier the same day hit `finish=length` with 8073/8192 reasoning tokens four times over (17.5 min, no output). No `reasoning` budget is sent (`llm_client.py:_build_payload`).
- **QA truncates silently.** sample61's VLM QA response: `out=8101 finish=length`, 38 results for 63 regions, and the backend logged `QA passed … Pipeline complete!` — OpenRouter's response-healing closes the JSON so it parses. 25 regions got no verdict. Correctness gap, not touched.

And the backend's 10-minute stale threshold (`recovery.rs:83`, 5-minute sweep, no worker heartbeat) re-dispatches any stage that runs longer, which sample222, 61 and 93 all do now; the duplicate is skipped only after the original finishes (`COMPLETED (not PENDING), skipping`). Every stage must finish under 10 minutes or heartbeat — the design constraint the phase-separation has to meet.

## Logging added for this gate (worker, deployed to the stack mid-run)

The cleanup step emitted no line of its own on the success path; the only trace of a 15-minute stage was ONNX Runtime's `VerifyOutputSizes` warning on stderr. Added: `services/stage_timer.py`; `[CTD] crop WxH -> fed WxH (MP) in Ns (us/px)`; one `[Cleanup] region (x,y wxh) crop WxH: kept|rejected … | ctd= mask= telea|aot= recheck= residual= encode= total=` line per region including every `None` path; `[Cleanup] uploaded …`; `[OCR] stage timings: …` at the callback; `[RQ Worker] Job … (stage) started, attempt a/b, Ns since enqueue` / `completed in Ns` for every job; LLM `Tokens … reasoning=N finish=… (tok/s)` on every call. Tests in `tests/test_stage_timer.py`; gates green (556 passed).

## Status

- Quality: on target where it can be measured; two pages need a canvas look because the scorer only sees "more pixels changed than R2".
- Time: **fails** — every fixture's OCR stage is over R2's whole-pipeline time, three of six exceed the backend's 10-minute re-dispatch threshold, one exceeds the harness window. Root cause measured and documented; fix is the phase-separation design (per-page cleanup job, one page-scale CTD pass, recheck dropped or replaced), tracker R3 addenda.
- R3f/R3g: not started, per the user's ordering (R3h first).
