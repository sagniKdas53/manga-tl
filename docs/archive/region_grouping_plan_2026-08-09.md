# Region grouping — what to change, and how to know it worked (2026-08-09)

Successor to `region_threshold_validation_2026-08-08.md` (measurement) and
`region_merge_prior_art_2026-08-08.md` (prior art). Written after reading the deep-research
report `docs/Manga Translation Unit Research with Visual References.pdf` (untracked; it is the
answer to `research_brief_region_merging.md`).

This document answers three questions: **should the worker adopt what everyone else does**,
**how do we change the benchmarks so they can tell us**, and **what maintenance does the worker
need**.

---

## 0. The three things that matter

1. **A dataset now exists that annotates our exact bug, ~14,900 times.** Manga109-v2026 (ICML
   2026 workshop) re-annotated Manga109 and its single largest fix category is *under-segmented
   speech balloons* — "multiple connected speech balloons annotated using a single bounding box"
   split into "multiple regions corresponding to individual speech balloons". That is BUG-2,
   verbatim, at a scale we cannot hand-annotate. See §2. **This is the highest-value item in this
   document** and it did not exist when the prior-art doc was written.

2. **Our OCR corpus cannot measure region quality, because it *is* the buggy region output.**
   `corpus/ocr/*/regions.json` was generated by the production path at `threshold_ratio=2.0`, and
   the stored transcriptions are keyed to those boxes. Measured: `sample30`'s corpus has 4 regions;
   the page has 7 balloons. We need a *separate* benchmark that scores boxes, not text. See §4.

3. **The threshold is the wrong thing to keep tuning.** Research and prior art agree, and for the
   same reason: `0.35` is one gate doing four jobs. Fix the structure and the constant stops
   mattering. Ranked worker changes in §3.

**Decisions I need from you** are collected in §7.

## 1. What the research changes

### It confirms (no action needed beyond proceeding)

- The working conclusion holds. "The application of a single, global distance threshold evaluated
  via transitive closure is fundamentally incompatible with the spatial typography of comic
  layouts." Our `0.35` is a compensator, not a parameter.
- The four missing gates named in the prior-art doc are the right four: local (pairwise)
  normalisation, angle gate, MST + adaptive cut, per-region orientation.
- **Minimum edge gap is the correct distance metric** — which is what we already compute
  (`merge_regions.py:123-130`). Centroid distance would be actively wrong for vertical CJK,
  because two long adjacent columns have distant centroids. One thing we got right for free.

### It corrects us on two points

**(a) `1.5` and `0.35` are not comparable — the denominator, not the numerator, is the bug.**
This was open question §5.1 in the prior-art doc; it is now answered. Both sides measure edge
gap. The difference is entirely normalisation:

```
theirs:  gap / max(width_A, width_B)        <- local, pairwise
ours:    gap / mean(width of every fragment in the call)   <- global, page-wide
```

For vertical CJK the column *width* is an excellent font-size proxy (characters sit on a square
em-grid), so under local normalisation the ratio literally reads as "how many characters of white
space". `1.5` then means "join these two columns if less than 1.5 characters apart" — a rule you
can state in words. `0.35` means nothing you can state in words; it is one-third of a page-average
character, which on a page mixing a shout with a caption is nobody's character.

**The practical consequence: switching to local normalisation should let the threshold go back up
to ~1.0–1.5, and — more importantly — make it transfer between pages.** That is the whole reason
no single value fitted all seven of our pages.

**(b) Rigaud's stopping rule will not port to our fragment boxes.** The prior-art doc listed
"consider Rigaud" as item 5 and called it the highest ceiling. Downgrade it. Persistence-style
stability rules need dozens of primitives to produce a plateau; Rigaud dilates *character-level*
connected components (50–100 per balloon), whereas our OCR fragments are already line-level and
number 2–6 per balloon. With N=4, one merge moves the count 25% and any "plateau" is
indistinguishable from noise. The count falls from N to 1 in one step.

Note the precise scope of this correction: it kills *porting the dilation rule onto our boxes*.
Running Rigaud as intended — on the bubble crop pixels, before OCR — is untouched by the argument,
because there the component count is large. It remains available, and remains a large change.

I would not treat the report's "confidence is absolute" here as absolute; the underlying argument
about sparse discrete sets is sound, but it is reasoning from first principles, not from a
measurement anyone has published. It is cheap to settle empirically (§4.5, experiment E5) and we
should, before formally closing the option.

### It unlocks one thing

Q5 asked how to evaluate without ground truth. The answer turned out to be that we no longer have
to — see §2.

## 2. Manga109-v2026: ground truth for exactly our bug

**What it is.** *Manga109-v2026: Revisiting Manga109 Annotations for Modern Manga Understanding*
(Baek, Miyai, Onohara, Ikuta, Aizawa), arXiv:2605.21182. Five categories of annotation defect
fixed across Manga109's 147,918 text boxes:

| type | issue | cases |
|---|---|---|
| 5 | **under-segmented speech balloons** — connected balloons in one box, now split per balloon | **~14,900** |
| 1 | inaccurate transcriptions | ~9,200 |
| 4 | overlapping text and onomatopoeia | ~4,300 |
| 3 | missing text annotations | ~800 |
| 2 | overly large boxes covering multiple text regions | ~50 |

Type 5 is our BUG-2. Type 2 is our chaining failure. Type 4 is the SFX-versus-dialogue boundary
that made two of our seven hand counts judgement calls.

**Why this matters more than anything else here.** Rigaud (2020) could only evaluate his method by
eye because no such annotation existed, and the paper closes by asking for it. We inherited that
constraint and were about to spend real effort hand-annotating 40 pages to escape it. That effort
is now largely unnecessary: we can evaluate a merge algorithm against thousands of annotated
connected-balloon cases, offline, for free, in a loop that takes seconds.

**Licensing — the catch, and it is manageable.**

- **Manga109** proper: *"The dataset can be used solely for academic purposes."* Not usable here.
- **Manga109-s**: 87 of 109 volumes cleared for commercial use, explicitly including *"using
  results, or portions of results, obtained from machine learning experiments … for commercial
  use"*. Distributed via HuggingFace (`hal-utokyo/Manga109-s`), gated behind an agreement form.
- **No redistribution, either version.** So: usable for local evaluation and tuning; **must not be
  committed to `corpus/`**, not even the private one, and no page images may ship. Attribution
  ("courtesy of [author]") is required if we ever publish results.

That fits our existing discipline — `corpus/samples/` is already gitignored third-party scans.
Manga109-s would sit *outside* the repo entirely, at a path given by an env var, with only derived
*scores* committed.

**What I could not verify:** whether the v2026 annotations are downloadable today or only
described in the paper, and whether they are keyed to Manga109-s's 87 clearable volumes or to the
full 109. Both are gating facts. Resolving them is task T0 in §6, and it is a form-filling job,
not an engineering one.

## 3. Worker changes

Ranked by payoff per unit of risk. Each is independently testable against the benchmark in §4, and
**each should be measured before the next is added** — that is the point of building the harness
first. Blast radius for all of them is the same and it is small: `impact(merge_ocr_regions,
upstream)` on `manga-tl-worker` returns **LOW** — 1 direct caller (`process_ocr`), 1 process,
1 module.

### C1 · Local pairwise normalisation *(do this first, alone)*

`merge_regions.py:100-110` computes `avg_width`/`avg_height` once over the whole call and uses it
for every pair. Replace with a per-pair yardstick:

```python
# today (global, computed once)
char_size = avg_width if reading_direction == "rtl" else avg_height
max_vertical_gap = char_size * threshold_ratio

# proposed (local, computed per pair inside the i/j loop)
char_size = max(r1["width"], r2["width"]) if vertical else max(r1["height"], r2["height"])
```

Smallest diff in the file, and it is the reason our value does not transfer across pages. Expect
the best threshold to rise toward 1.0–1.5. **Do not ship C1 together with a threshold change** —
sweep the threshold again *after* C1 and let the benchmark pick it.

### C2 · Angle and size-similarity gates

Both are cheap, and they are what lets the distance budget be forgiving:

- **angle** — vector between the two box centroids; for vertical text, reject the merge if it
  deviates more than ~30–35° from horizontal (vertical columns stack sideways). Prior art uses
  0.2π ≈ 36° (manga-image-translator) and `cos > 0.866` ≈ 30° (comic-text-detector).
- **size similarity** — reject if `max(fs)/min(fs) > 1.3`. This alone would stop a shout from
  absorbing a caption.

Expected effect: recovers `sample27`'s over-split (the one page tightening cost us) without
reintroducing cross-balloon fusion, because the gap that reopens is gated on alignment instead.

### C3 · Orientation per region, not per book *(BUG-6)*

`reading_direction` is a **binding** setting misused as a **text-orientation** flag. Replace with
aspect-ratio majority vote over the fragments in the group: `height/width > 1.2` → vertical,
`width/height > 1.2` → horizontal, tie → component-spacing anisotropy, then fall back to the
binding direction. Single-fragment regions need no vote — grouping is moot.

Already evidenced: `sample23` is 61/61 horizontal fragments and collapses to 2 regions under the
`rtl` assumption but yields exactly the hand count of 17 under `ltr`, stably across 0.25–1.0.
Note this is currently validated on **one** page; C3 must be checked against a genuinely vertical
page before shipping, to confirm detection does not flip the common case.

### C4 · MST with adaptive edge cutting, replacing transitive closure

Build a minimum spanning tree over the fragments, cut edges exceeding an adaptive statistical
threshold (`mean + 2σ` of observed normalised distances). This is the structural answer to
unbounded chaining that BUG-4 was reaching for. Larger change than C1–C3, and its benefit partly
overlaps theirs, so **measure C1–C3 first**; C4 may turn out to buy less than expected once the
gates are in.

### C5 · Rigaud dilation on bubble crops — parked

Not a drop-in: it runs on the bubble crop image before OCR, replacing the merge heuristic rather
than tuning it. Highest ceiling, largest change, and §1(b) removes the cheap version of it. Revisit
only if C1–C4 plateau below target.

## 4. The benchmark plan

### 4.1 Why the current benchmark cannot answer this

`corpus/ocr/` holds 291 regions across 40 samples. Those regions **are the production output of
the code we are trying to fix** — `meta.json` says so: *"Region proposals come from the production
path … so detection is held constant … and only transcription is being scored."* That was a
deliberate, correct choice for measuring OCR engines. It makes the corpus useless for measuring
segmentation, and worse, it means the stored ground-truth text for a fused region is a
transcription of *two characters' dialogue concatenated*.

The evidence, comparing what the corpus stores against the sweep in the validation doc:

| sample | corpus | probe @2.0 | probe @0.35 | hand count |
|---|---|---|---|---|
| `sample3` | 5 | 6 | 9 | 9 |
| `sample1` | 3 | 3 | 4 | 4 |
| `sample30` | 4 | 4 | **7** | **7** |
| `sample16` | 9 | 8 | 9 | 10 |
| `sample9` | 11 | 11 | 15 | 18 |
| `sample27` | 16 | 15 | 20 | 18 |
| `sample23` | 2 | 2 | 2 | 17 |

The corpus column tracks the `2.0` column, not the truth column. (Small differences are the
unmatched path deployed at `1.0`, plus regions blanked during review.)

**Two consequences.**

1. **A separate benchmark is needed**, scoring boxes against boxes with no text involved. It costs
   nothing to run — no engines, no network, no 60-second budget — so it can run on every commit.
2. **Do not spend another rupee on OCR or translation corpus runs until the region fix lands.**
   Every stored candidate is keyed to a region box. Fixing segmentation raises the region count by
   roughly a third on the pages we measured (49 → 66 across the seven), invalidating all of it.
   This is the "bundle into one cloud pass" rule from the handoff, and it now has a number on it.

### 4.2 The metric: RDCL error types with an asymmetric cost

Adopt the ICDAR2019 RDCL framework — the standard for exactly this problem. Build a bipartite
overlap graph between proposed and ground-truth regions and classify every mismatch:

| error | meaning | our stance |
|---|---|---|
| **Merger** | one proposal overlaps ≥2 ground-truth regions | **the expensive one** |
| **Split** | one ground-truth region covered by ≥2 proposals | cheap |
| **Miss** | ground-truth region matched by no proposal | expensive (text vanishes) |
| **False detection** | proposal overlapping no ground-truth region | cheap-ish (junk region) |

Our costs are asymmetric and we should say so numerically rather than in prose. A merger fuses two
speakers into one translator input and paints them out under one flat fill — unrecoverable. A split
sends two strings that usually typeset back into the same balloon acceptably.

```
Cost = λ·M + S          with M, S measured as text area, and λ = 5
```

λ=5 is the report's suggested starting point, not a derived constant. Set it once, write down why,
and never tune it — it encodes a product decision, and a tunable λ would let us optimise the metric
instead of the pipeline.

**This also settles a contradiction in our own docs.** `region_proposal_defects_2026-08.md` still
says "under-segmenting is recoverable, over-segmenting is not", one sentence after saying merging
can happen later. The measurements support the opposite, and λ=5 makes the intended direction
explicit. That sentence should be corrected when this lands.

### 4.3 Ground truth: two tiers

**Tier A — Manga109-s + v2026 annotations (primary).** Thousands of cases, free, already
annotated, and the type-5 subset is precisely our failure mode. Lives outside the repo at
`$MANGA109_ROOT`; the benchmark skips tier A with a clear message when unset, so the repo stays
runnable without it.

**Tier B — our 40 pages (secondary, and still worth doing).** Tier A is Manga109's corpus, whose
typography and scan quality are not ours, and it will not contain our YOLO detector's failures at
all — tier A scores *the merge algorithm*, tier B scores *our pipeline*. Keep both.

For tier B, annotate region boxes only — no transcription — which is far cheaper than what we
feared. `scripts/build_ocr_corpus.py` already generates review HTML (`write_review_html`) and
ingests corrections (`apply_review`); extend that rather than building an annotation tool. If two
of us annotate, report Krippendorff's α and treat α ≥ 0.80 as the bar; below it, the guidelines are
ambiguous rather than the annotators being careless.

Write the annotation guideline *before* annotating, and make it resolve the cases that made our
hand counts wobble: does a sub-caption inside a balloon count separately (`sample9`), do two column
groups in one balloon count as one (`sample27`), does an SFX overlapping dialogue split it.

### 4.4 The harness

Extend `scripts/region_proposal_probe.py` into `scripts/benchmark_regions.py`. It already loads a
page, runs YOLO + PaddleOCR, and calls `merge_ocr_regions` under an arbitrary configuration — which
is most of the work. What it needs:

- a **ground-truth loader** for both tiers,
- **RDCL matching + the cost function** (`bench_common.iou` already exists; the bipartite matching
  does not),
- a **configuration matrix runner** so a whole ablation is one command,
- **caching of the OCR fragment stage**, so a sweep re-runs only the merge. This is the difference
  between a 3-second loop and a 10-minute one, and it is what makes the tuning interactive.

Report per-configuration: mergers, splits, misses, false detections, asymmetric cost, and cost
broken down by tier.

### 4.5 The experiments

The harness exists to answer specific questions. In order:

| # | question | configuration | what would change our mind |
|---|---|---|---|
| **E1** | Does the corpus reproduce our seven-page finding at scale? | current code, threshold sweep, tier A | if `2.0` is *not* worst on Manga109, our sample is unrepresentative and the whole line of work needs re-examining |
| **E2** | Does local normalisation make the threshold transfer? | C1 on, threshold sweep | per-page optimal thresholds should cluster tightly instead of ranging 0.35–1.5; if they scatter as much as before, C1 is not the mechanism we think it is |
| **E3** | Do the gates let the budget loosen? | C1 + C2, threshold sweep | cost at threshold ~1.5 should beat the best C1-only cost; if not, the gates are redundant here |
| **E4** | Is MST worth it once gates exist? | C1 + C2 + C4 | a clear cost drop justifies it; a marginal one parks C4 |
| **E5** | Does a plateau actually exist on line-level boxes? | count regions vs. threshold, per balloon, tier A | settles §1(b) empirically. If plateaus do appear on real data, per-balloon adaptive thresholding is back on the table and is *better* than any constant |
| **E6** | Does orientation voting hold on vertical pages? | C3, tier A vertical-only subset | it must not regress the common case; this is C3's ship gate |

E1 is also the honest test of everything we concluded from seven pages. Run it first, and run it
before writing any of C1–C4, so that a negative result costs us a day rather than a rewrite.

## 5. Worker maintenance: `OCR_MERGE_THRESHOLD`

A correction to what I told you earlier, because I was more dismissive than the code warrants.
**The variable is not dead.** There are three call sites and it governs two of them:

| site | path | threshold |
|---|---|---|
| `ocr.py:605` | split fragments **inside** a YOLO bubble | **hardcoded `2.0`** — ignores the env var |
| `ocr.py:663` | merge fragments matched to **no** bubble (SFX, narration) | `OCR_MERGE_THRESHOLD` |
| `ocr.py:1152` | fallback path when bubble detection is not used | `OCR_MERGE_THRESHOLD` |

So the accurate statement is narrower: **the env var cannot affect the behaviour we measured and
fixed**, because that behaviour lives at `:605` behind a hardcoded literal. Turning the knob in
`docker-compose.yml` would never have moved any number in the validation doc. It does change SFX
and narration grouping, and on a page with no detected bubbles it governs everything.

Three defects worth fixing regardless of C1–C4:

1. **`docker-compose.yml:220` deploys `1.0`; the code default is `0.50`.** Double. Flagged as fix
   #1 in `render_quality_gap_2026-08-05.md` §D4 and never applied. Deployed behaviour has therefore
   never matched any tested configuration — an unpleasant thing to discover mid-investigation.
2. **A hardcoded `2.0` at `:605` silently overrides configuration.** Whatever value C1–C4 settle
   on, it should be named and configurable, and the override should carry a comment saying why the
   in-bubble path differs from the others — because it genuinely should differ, and that is not
   obvious.
3. **Three call sites, two policies, no shared vocabulary.** After C1–C4 the merge function will
   take several parameters; passing them positionally from three places will rot. Group them into
   one config object built once in `process_ocr`.

None of this is urgent on its own. All of it is nearly free while the file is already open.

## 6. Sequence

**T0 — Manga109-s access (blocking, do today, not engineering).** Apply for Manga109-s on
HuggingFace; establish whether v2026 annotations are downloadable and whether they cover the 87
commercial-cleared volumes. Everything in §4.3 tier A depends on this, and the form may take days
to clear, so start it before writing code. If it falls through, tier B carries the plan alone at
noticeably lower confidence and higher annotation cost.

**T1 — build the harness (§4.4).** Half a day. No worker changes. Ends with E1 running.

**T2 — run E1.** The audit of our own conclusions. Everything downstream is contingent on it.

**T3 — C1, measure (E2). Then C2, measure (E3). Then C3, measure (E6).** One change per
measurement. Worker tests for each; the four gates in `worker/CLAUDE.md` all apply, baseline 315
passed. Commit in the worker submodule and push before bumping the parent pointer.

**T4 — decide on C4 from E4, and on C5 from E5.**

**T5 — the bundled cloud re-run.** Only now. All region changes land together, `corpus/ocr` is
rebuilt, every candidate is regenerated once. Also fix the compose value (§5.1) in this batch, so
deployed and tested configurations finally coincide.

**T6 — tier B annotation**, in parallel with T1–T4 whenever there is spare attention. It is not on
the critical path if T0 succeeds.
